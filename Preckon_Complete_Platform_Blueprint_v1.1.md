# Preckon — Complete Platform Blueprint
**Version 1.1 | August 12, 2026**

## 1. Vision
Preckon is an AI-native, end-to-end construction operating platform where projects are designed, engineered, estimated, procured, built, controlled, and handed over through one connected construction model.

**North Star:** Tender / Idea → Requirements → Design → Engineering → Drawings → Quantities → BOQ → Estimate → Bid → Procurement → Schedule → Construction → Cost Control → QA/QC → Commissioning → As-Built / Digital Twin.

Preckon’s original product vision remains unchanged. **AI-native CAD/BIM authoring, parametric automation and documentation capabilities are an expansion of Preckon Draw / Design Studio — not a pivot of the platform.** Preckon should meet or exceed relevant capabilities demonstrated by leading AI design platforms such as ArchiLabs, while connecting design directly to TenderLogix, quantities, BOQ, estimation, procurement, project delivery, cost control, quality and handover. The goal is to minimize customer dependence on multiple disconnected platforms for core construction workflows.

## 2. Product Principles
1. One connected construction model, not disconnected modules.
2. AI interprets intent; deterministic engines execute geometry, calculations and rules.
3. Construction objects, not pixels or isolated CAD lines.
4. Every design object can connect to quantity, BOQ, cost, schedule, procurement and field status.
5. Human approval for engineering-, code-, safety- and contract-critical decisions.
6. Open interoperability: IFC, DWG/DXF, PDF, APIs and industry formats.
7. Integrate first where necessary; progressively replace incumbent workflows.
8. Construction-domain knowledge and lifecycle relationships are the moat.

### 2.1 Vision Guardrail — No Product Pivot
Preckon is **not being repositioned as an ArchiLabs competitor or an AI-CAD point solution**. The established Preckon platform scope remains the governing product strategy. ArchiLabs is used as a capability benchmark for the Draw / Design Studio domain.

The architecture therefore follows this rule:

```text
Original Preckon Vision
+ ArchiLabs-class Design / BIM / AI Authoring capabilities inside Draw
+ One PCM connecting design to every downstream construction workflow
= Preckon Complete Platform
```

A design feature should be implemented in a way that strengthens downstream Preckon workflows. For example, a wall generated by AI must be capable of participating in quantity takeoff, BOQ, estimation, procurement, schedule, change control, field progress, quality and handover rather than existing only as geometry.

## 4. Preckon Construction Model (PCM)
PCM is broader than BIM. It is the persistent model linking physical, documentary, commercial and execution information.

```text
Project
├── Requirements / Tender / Specifications
├── Site / Buildings / Levels / Zones / Spaces
├── Construction Objects
├── Models / Drawings / Sheets
├── Quantities / BOQ / Estimate / Budget
├── Schedule / Procurement / Contracts
├── RFIs / Submittals / Changes
├── Progress / Quality / Safety
└── Assets / Handover
```

A wall stores geometry, location, type, materials, fire/acoustic properties, classification, specification links, drawing/revision provenance, quantity rules, BOQ/cost mapping, activities, procurement, RFIs, submittals, changes, installation and inspections.

Relationship example: `Door D104 → specified_by → Spec → measured_by → Quantity → contributes_to → BOQ → budgeted_by → Cost Item → procured_by → PO → inspected_by → ITP`.

## 5. Design Studio Architecture
### UX
```text
Project Tree | 2D/3D Canvas | AI Copilot
             |               | Intent / Suggestions / Validation / Impact
-----------------------------------------------------------------------
Properties | Layers | Versions | Quantities | BOQ | Issues
```
Support direct graphical manipulation, parametric manipulation and natural-language AI manipulation.

### Execution
```text
User Intent
→ Intent Interpreter
→ Planning Agent
→ Structured Tool Calls
→ Deterministic Geometry/BIM/Rules Engines
→ Validation
→ Transaction Preview
→ Approval if required
→ Commit + Audit + Downstream Events
```
Never let an LLM directly mutate production model state.

### Geometry & Parametrics
Use a geometry abstraction supporting curves, polygons, solids/B-rep, booleans, transforms, constraints, snapping, intersections, spatial indexing, measurements and rendering. PCM must not depend tightly on one geometry vendor.

Maintain dependencies such as `Grid → Columns → Beams → Slabs → Openings`. Parameter changes trigger controlled recomputation.

Every operation records author, source, timestamp, affected object IDs, before/after state, AI rationale, validation and approval. This powers undo/redo, audit, collaboration and explainability.

## 6. Drawing Intelligence
```text
PDF / DWG / DXF / IFC / Image
→ Normalize → Classify → Extract vectors/text/geometry
→ Recognize symbols/objects → Spatial reasoning
→ Reconstruct objects → Cross-sheet reconciliation
→ Confidence scoring → Human validation → PCM
```
MVP priority: levels, grids, rooms, walls, doors, windows, columns, dimensions and annotations. Next: beams, slabs, ceilings, stairs, fixtures and MEP.

Every AI-created object retains source, confidence, assumptions, alternatives and verification state. Low-confidence items enter review rather than silently entering quantities.

## 7. AI Intelligence Core
### Agents
Preckon Orchestrator coordinates Tender, Requirements, Drawing, Architectural, Structural, MEP, Specification, Standards, Quantity, BOQ, Estimation, Planning, Procurement, Commercial, RFI, Submittal, Quality, Safety, Change Impact and Project Controls agents.

Each agent has explicit inputs, tools, permissions, output schema, confidence, evidence, validation and escalation rules.

### Tool-first execution
Agents invoke controlled functions such as `find_objects`, `create_wall`, `change_type`, `calculate_area`, `detect_clash`, `measure_quantity`, `map_boq_item`, `price_item`, `query_specification`, `calculate_change_impact` and `draft_rfi`.

Context hierarchy: session → project → PCM objects → organization standards → project specifications → jurisdiction codes → approved knowledge → authorized historical projects.

Use model routing: LLMs for intent/reasoning; vision for drawings/photos; document models for tenders/specs; geometry ML for recognition; embeddings for retrieval; forecasting/optimization for controls. Keep providers behind abstractions.

## 8. Construction Knowledge Graph
Nodes include project, space, design object, material, assembly, specification, code, drawing, revision, quantity, BOQ, cost, activity, vendor, contract, PO, RFI, submittal, change, inspection and asset.

A question such as **“What happens if Wall Type W4 changes?”** becomes graph traversal plus deterministic recalculation, followed by AI explanation.

## 9. Quantity → BOQ → Cost Engine
Measurement must be rule-driven and configurable. Support gross/net wall areas, deduction rules, concrete, reinforcement, formwork, finishes, painting and MEP measurements.

Mandatory traceability: `BOQ line → quantity calculation → PCM objects → source model/drawing/revision`. Clicking a quantity highlights contributing objects.

When geometry changes: mark affected measurements dirty → recompute → produce BOQ delta → calculate estimate delta → preserve approved baseline → invoke change-control rules.

## 10. Tender-to-Design Workflow
```text
Tender package
→ classify documents
→ extract requirements/specifications
→ compliance matrix
→ interpret drawings
→ detect missing information
→ clarification/RFI candidates
→ requirements model
→ import/generate design
→ validate design
→ takeoff → BOQ → estimate → bid
```
This is a key advantage over design-only platforms.

## 11. Flagship Change Intelligence
Example: change Level 4 office partitions from 100 mm to 150 mm acoustic walls.

Preckon should automatically identify:
- model/drawing revisions
- added/removed quantities
- BOQ and cost delta
- schedule exposure
- affected procurement/POs
- affected shop drawings, submittals and RFIs
- already-installed work
- approval requirements

The user receives an impact report before committing downstream commercial changes.

## 13. Standards & Classification
Build a standards service rather than hard-coding rules. Support project/jurisdiction profiles and mappings for IFC, ISO 19650 concepts, Uniclass/OmniClass/MasterFormat where relevant, GCC authority requirements and customer standards.

Every rule records jurisdiction, edition/version, source, effective date and applicability. AI must surface uncertainty/conflicts.

## 14. Integration & Replacement Strategy
### Phase A — Coexist
Integrate/import/export with Autodesk ecosystems, IFC, DWG/DXF, PDF, Excel, scheduling, ERP/accounting and common document platforms.

### Phase B — Reduce dependency
Replace takeoff, BOQ, tender, drawing intelligence, selected design automation, document control and commercial workflows.

### Phase C — Native platform
Preckon becomes the system-of-work for design-through-handover while retaining open exchange for consultants and owners.

Do not attempt a command-by-command AutoCAD/Revit clone. Replace high-value workflows through AI, parametrics and connected lifecycle intelligence.

## 15. Enterprise Security
Multi-tenant isolation; project RBAC/ABAC; SSO/SAML/OIDC; MFA; encryption; regional storage; audit; object permissions; AI data isolation; retention/legal hold; backup/DR; SOC 2/ISO 27001-ready controls; API gateway; upload scanning and secrets management.

## 17. API Architecture
API-first with stable global object IDs, optimistic concurrency and idempotent commands. API domains: Projects, Documents, Models, Objects, Geometry, Drawings, Quantities, BOQs, Estimates, Schedules, Procurement, RFIs, Submittals, Changes, Quality, AI and Integrations.

Use asynchronous jobs for heavy model/AI operations and webhooks/events for integrations.

## 18. AI/Data Governance
For operational AI output retain model/version, prompt/context reference, tools used, evidence, confidence, validation and user acceptance/rejection.

Do not train on customer project data by default. Separate generated suggestions from approved engineering records.

## 19. Accuracy Framework
Accuracy is a core product feature. Use confidence thresholds, deterministic measurement, provenance, visual overlays, cross-document reconciliation, rule checks, human review queues, real-project regression datasets and golden drawing/BOQ sets.

Track object-recognition precision/recall, dimensional tolerance, quantity variance, BOQ mapping accuracy, critical false-negative rate and user correction rate.

RFIs, submittals, procurement, cost control, planning, field workflows, QA/QC, mobile and comprehensive change intelligence.

## 31. Strategic Moat
The moat is not the chatbot and not merely drawing generation. It is the accumulated combination of:

**PCM + construction knowledge graph + deterministic construction tools + project history + quantity/BOQ traceability + lifecycle change propagation + domain agents + customer workflows.**

The more of the lifecycle Preckon connects, the harder it becomes for a point solution to reproduce the project context.

## 32. Example End-State Experience
A contractor uploads a tender package and asks:

> Review this project, identify scope and risk, build the preliminary design model, produce the BOQ and estimate, and show what information we still need before bidding.

Preckon classifies documents, extracts requirements, interprets drawings, builds PCM objects, flags contradictions, generates clarification candidates, creates/updates the design, measures quantities, maps BOQ items, prices them and presents evidence/confidence.

Later the architect changes the façade. Preckon updates geometry, quantities, BOQ, cost, procurement exposure and schedule implications, identifies affected approved documents and routes the change for review.

During construction the same objects accumulate installation, inspection and commissioning state. Handover is produced from the same connected model.

That is the practical meaning of **Preckon’s original end-to-end vision with ArchiLabs-class AI-native design capabilities added to Draw / Design Studio.**
